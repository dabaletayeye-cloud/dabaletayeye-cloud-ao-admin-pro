# 自定义模块默认保留与版本规则

配置文件：前端 `src/config/edition-rules.json`，全栈项目中对应 `react/src/config/edition-rules.json`。

默认开启规则，并在所有版本保留自定义模块，包括极简版。正常注册在 `src/modules/<模块ID>/module.json` 中、且 ID 不在 `builtInModules` 清单中的模块，视为自定义模块。新增模块后执行 `npm run generate:registry` 或重启开发服务。不要直接编辑生成的 `src/generated/registry.ts`。

## 配置示例

保留文件里的 `version` 和 `builtInModules`，按需要修改这些字段：

```json
{
  "enabled": true,
  "preserveCustomModules": true,
  "editions": {
    "saas": {
      "include": ["device"],
      "exclude": ["internal-tools"]
    },
    "erp": {
      "preserveCustomModules": false,
      "include": ["device", "project"]
    },
    "minimal": {
      "preserveCustomModules": false
    },
    "full": {
      "exclude": ["internal-tools"]
    }
  }
}
```

上面是要合并的字段示例，不是完整配置文件。`device`、`project` 等是模块 ID 示例，需要替换成自己的 ID；规则不会自动创建模块。

- `enabled=false`：关闭扩展规则，恢复原有内置版本筛选方式。
- 全局 `preserveCustomModules=false`：关闭默认保留，可再通过版本规则单独开启。
- 版本内 `preserveCustomModules`：覆盖全局默认值。
- `include`：额外启用指定模块，可包含内置或自定义模块。
- `exclude`：排除指定模块，优先于 `include` 和默认保留。
- `core`：始终保留，不允许排除。
- 全部版本来就包含所有已安装模块，因此关闭“默认保留”不会单独隐藏全部版里的模块；需要用该版本的 `exclude`。

版本 ID：`minimal`、`erp`、`oa`、`saas`、`ecommerce`、`devplatform`、`bi`、`demo`、`ai`、`cms`、`crm`、`full`。

`builtInModules` 用于区分模板内置模块和新增模块，通常保持默认。不要把新业务模块加进去，否则它会被当成内置模块按版本筛选。

## 生效范围

HTTP 后端优先读取前端模块目录旁的 `src/config/edition-rules.json`；Mock、菜单、路由、权限入口与裁剪脚本采用相同规则。全部版会把自定义模块保留为独立分类，不重复塞入每个内置版本分类。横向与侧边导航采用同一菜单构建逻辑。

首次升级需要重启后端。修改规则后刷新版本设置；前端开发环境会重新加载 JSON，正式部署需要重新构建前端。独立部署后端时可通过 `EDITION_RULES_FILE` 指向同一份规则文件；没有前端目录和指定文件时使用后端 `src/main/resources/edition-rules.json`，部署时需同步这份配置。

模块保留规则不授予角色权限，也不绕过商户数据隔离与接口访问范围限制。

## 裁剪与回退

```powershell
npm run clean:edition -- --edition=saas --dry-run
```

先检查保留/移除清单。默认自定义模块不会被裁剪；关闭保留或明确排除后，相关模块可能进入移除清单，仍按原流程备份和回退。若被保留模块依赖一个明确排除的模块，裁剪会拒绝执行，需要调整规则。预览后修改规则也会使旧裁剪计划失效，必须重新预览。

普通版本切换只隐藏入口，不删除源码和业务数据。

# 多地区与多商户

## 同时运行平台端和商户端（连接后端）

平台端使用 `.env` 中的 `admin-web / sysuser`，运行 `npm run dev`，默认端口 5174。

商户端使用 `.env.merchant` 中的 `merchant-web / merchant`，在另一个终端运行 `npm run dev:merchant`，端口固定为 5175。若尚无 `.env.merchant`，从 `.env.merchant.example` 复制后配置。两端都使用 HTTP 接口。

后端需要开启 `TENANCY_ENABLED=true`，并允许 `merchant-web` 访问商户业务接口。由平台管理员创建真实地区、商户和商户账号，完成账号绑定后再登录商户端。

功能适用于 SaaS、电商、CRM 和全部版，默认关闭。

纯前端展示编辑 `src/config/tenancy.json`：

```json
{ "enabled": true, "regionMode": "SINGLE_REGION" }
```

- `SINGLE_REGION`：每个商户对应一个地区。
- `MULTI_REGION`：每个商户可关联多个经营地区。
- `enabled: false`：关闭演示入口。

运行 `npm run dev:mock`。系统管理上方增加“地区管理”和“商户管理”。顶部按地区筛选商户，并切换业务范围；切换会重新挂载页面，清除旧商户表单。Mock 内置 4 个地区、6 个示例商户，新增商品、文章及上传文件按商户分开保存，刷新后重置。

HTTP 模式由后端 `.env` 的 `TENANCY_ENABLED` 和 `TENANCY_REGION_MODE` 控制，前端 JSON 不控制服务器权限。首次启动需要后端执行 V19 迁移。平台管理员创建地区和商户，再绑定独立账号；账号类型和客户端规则仍然生效。商户客户端需要允许 `/api/tenancy` 及相应业务路径，绑定后重新登录。

已接入 ERP、内容和文件等真实业务接口；OA、服务器管理及其他平台功能不会对商户账号开放。地区关联用于筛选和归属，同一跨地区商户内部共享数据。

接口统一位于 `src/api/tenancy.ts`，HTTP 与 Mock 共用接口契约。`X-Merchant-Id` 由统一 HTTP 层发送，服务端验证归属。请求重试保留原请求的商户范围，切换商户不会让旧请求写入新商户。

测试：`node scripts/test-tenancy.mjs`、`npm run build:mock`。后端完整配置与迁移说明见后端项目的 `docs/多地区与多商户.md`。

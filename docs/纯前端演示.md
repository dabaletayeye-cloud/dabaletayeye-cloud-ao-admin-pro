# 纯前端演示

无需 Java 后端或数据库。在项目根目录运行：

```powershell
npm run dev:mock
```

先停止旧的前端 dev 进程，避免 5174 端口被占用后自动切到另一个端口。浏览器打开终端显示的地址。演示登录默认填写 `demo` / `demo123` 并完成页面上的验证。

演示账号在 `src/config/mock-auth.json` 配置 `username` 和 `password`，Mock 登录会校验这两项，登录页自动带出配置的账号。修改后刷新开发页面；已部署的静态站需要重新构建部署。该配置会打包进前端，只能填写演示凭据，不要放真实账号密码。HTTP 模式仍由后端认证，不受此配置影响。

`dev:mock` 自动使用 `.env.mock` 中的 `VITE_API_MODE=mock`，无需改动现有 `.env` 的后端联调配置。普通 `npm run dev` 仍使用 `.env`，因此可随时切回联调。

如需演示系统用户与业务用户分离，在 `src/config/mock-auth.json` 设置 `sysUserEnabled: true`，使用 `sysuser.username` / `sysuser.password` 登录（默认 `SysAdmin` / `admin123`）。系统用户在独立集合维护，原用户列表作为业务用户；设为 `false` 则恢复顶层 `username` / `password` 登录。HTTP 模式使用后端的 `SYSUSER_ENABLED`，不读取此 Mock 开关。

## 可演示功能

如需多用户类型/多客户端演示，编辑 `src/config/account-clients.json` 并设 `enabled: true`。默认管理端账号为 `SysAdmin / admin123`，会员为 `member / member123`，商户为 `merchant / merchant123`。登录页自动带出所选客户端默认类型的演示账号。

可在前端环境变量中设置 `VITE_AUTH_CLIENT_ID=mobile-app`、`VITE_AUTH_USER_TYPE=member` 后重启，用会员身份验证客户端限制。默认会员/商户客户端仅允许个人资料等认证功能，不能操作后台管理 API；这不会自动把后台模板变成独立会员网站。

多类型配置优先于 `mock-auth.json`。所有演示账号均公开打包到前端，业务变更在刷新后重置。真实客户端令牌有效期与 API 范围以 HTTP 后端 JSON 为准。

- ERP：商品、客户、供应商、订单、采购、库存、财务均有初始数据和增删改接口；支持 CSV 新增、商品库存同步、出入库流水、库存不足校验、采购审批、订单完成及报表聚合。
- OA：审批、考勤、公告、日程、组织架构均有演示数据；支持记录维护、重复打卡校验、审批状态变更和部门删除限制。
- 版本切换：所有预设都由现有裁剪配置计算，结合实际注册模块决定可用版本；与裁剪后自动选版兼容。
- 媒体库：带演示图片和文本文件，上传、预览、下载使用浏览器内存中的真实文件内容，不连接服务器。
- 工作台、图表、用户角色、系统设置、服务器和低代码页面继续使用已有 Mock 数据；AI 页面是前端交互演示，不会调用真实大模型。

业务数据与上传文件保存在当前标签页的内存中，整页刷新后恢复初始演示数据。版本选择、主题偏好保存在浏览器中。模拟动作不会改变真实数据库或操作真实服务器。

## 静态部署

```powershell
npm run build:mock
npm run preview
```

部署生成的 `dist` 目录即可。静态服务器需支持 SPA 路由回退到 `index.html`，以便直接打开 `/erp/products` 等地址。

## 验证

```powershell
node scripts/test-mock-mode.mjs
```

测试覆盖实际 ERP/OA 适配入口、登录、库存回滚、重复审批、CRUD、全部版本及文件上传下载；禁止任何 fetch 请求，以防模拟模式意外访问后端。

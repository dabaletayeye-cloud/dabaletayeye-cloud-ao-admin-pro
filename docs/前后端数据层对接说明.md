# 前后端数据层对接说明

本文档描述 `ao-admin-pro` 当前的数据层抽象、前后端接口契约、环境配置、鉴权约定、错误处理和联调流程。后端可以按本文档实现接口，前端无需修改页面组件，只需切换 API 模式即可从 mock 数据切换到 HTTP 服务。

## 1. 架构概览

页面只依赖 `src/api/` 导出的业务函数，不直接依赖 `fetch`、mock 数据或后端 URL。

```text
页面 / 组件
    ↓
src/api/*.ts              # 页面可调用的业务函数与 TypeScript 契约
    ↓
src/api/adapter.ts        # 根据 VITE_API_MODE 选择适配器
    ├─ adapters/mock.ts    # 本地数据 + 约 300ms 延迟
    └─ adapters/http.ts    # 原生 fetch + VITE_API_BASE_URL
```

核心文件：

| 文件 | 职责 |
| --- | --- |
| `src/api/types.ts` | DTO、分页结果、业务数据结构 |
| `src/api/adapters/types.ts` | 适配器完整接口 `ApiAdapter` |
| `src/api/adapters/mock.ts` | mock 数据源，支持基本增删改查与延迟模拟 |
| `src/api/adapters/http.ts` | HTTP 数据源，统一处理 URL、请求头、响应 envelope 和错误 |
| `src/api/adapter.ts` | 根据环境变量导出当前适配器 |
| `src/api/index.ts` | 页面使用的 API 函数总入口 |
| `src/hooks/useApiResource.tsx` | 页面通用的 loading/error/data 状态封装 |

## 2. 环境变量

在项目根目录创建 `.env.local`，或复制 `.env.example`：

```env
# mock 或 http，默认 mock
VITE_API_MODE=mock

# HTTP 模式的后端根地址，不要以 / 结尾
VITE_API_BASE_URL=http://localhost:8989
```

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| `mock` | 使用 `src/api/adapters/mock.ts`，所有方法 Promise 化并延迟约 300ms | 默认开发、UI 验收、无后端环境 |
| `http` | 使用 `src/api/adapters/http.ts`，请求 `VITE_API_BASE_URL + path` | 后端联调、测试环境、生产环境 |

Vite 在启动/构建时读取环境变量，修改 `.env.local` 后需要重启开发服务器。

## 3. HTTP 通用约定

### 3.1 请求地址

最终地址：

```text
VITE_API_BASE_URL + API path
```

例如 `VITE_API_BASE_URL=http://localhost:8989` 时，`GET /api/users` 请求地址为 `http://localhost:8989/api/users`。

### 3.2 请求头与鉴权

每次请求都会发送：

```http
Accept: application/json
Authorization: Bearer <accessToken>
Content-Type: application/json
```

其中 `Authorization` 仅在浏览器存储中存在 token 时发送。当前适配器从 `localStorage` 和 `sessionStorage` 的 `manga_workshop_tokens` 读取：

```json
{
  "accessToken": "eyJ..."
}
```

如果后端使用其他 token 存储键或登录返回结构，请修改 `src/api/adapters/http.ts` 的 token 映射，不要在页面中读取 token。

### 3.3 响应 envelope

推荐所有接口统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

约定：

- `code === 0` 表示成功。
- `code !== 0` 时前端抛出 `message`。
- HTTP 非 2xx 时前端抛出 `message` 或 `请求失败（HTTP 状态码）`。
- 当前适配器也兼容直接返回业务 JSON，但新接口建议统一使用 envelope。

分页接口的 `data`：

```json
{
  "list": [],
  "total": 120,
  "page": 1,
  "pageSize": 20
}
```

## 5. TypeScript 数据结构

### 5.1 通用分页

```ts

  page?: number;
  pageSize?: number;
  keyword?: string;
  status?: string;

  list: T[];
  total: number;
  page: number;
  pageSize: number;
}
```

```ts
  id: number;
  name: string;
  email: string;
  avatar: string;

  gender: string;
  role: string;
  roles?: string[];
  status: 'active' | 'inactive' | 'banned';
  joinDate: string;
```

### 5.3 角色与菜单

```ts
interface Role {
  id: number;
  name: string;
  code: string;
  description: string;
  userCount: number;
  status: 'enabled' | 'disabled';
  createdAt: string;
  permissions: string[];

type MenuType = 'catalog' | 'menu' | 'button' | 'external';

  id: number;

  permission: string;
```

菜单接口返回树形结构，`button` 节点通常作为 `menu` 节点的 `children` 返回。

### 5.5 仪表盘、分析、日志、字典

```ts
interface DashboardData {
  statCards: Array<{
    title: string;

    change: string;
    positive: boolean;
    icon: string;
  }>;
  monthly: Array<{ month: string; value: number }>;
  yearly: Array<{ month: string; visits: number }>;
```

其他 DTO 以 `src/api/types.ts` 为准：

- `VisitStatsData.daily`: `{ date, pv, uv, ip }[]`
- `VisitStatsData.sources/devices/regions`: `{ name, value, color/growth }[]`

- `dict`: `types` 和 `items` 两组数组，字典项通过 `typeId` 关联

## 6. 页面调用方式

页面应调用业务 API，不要直接调用 `fetch`：

```tsx
import { listUsers } from '@/api';
import { useApiResource, ApiState } from '@/hooks/useApiResource';

const resource = useApiResource(() => listUsers({ page: 1, pageSize: 20 }));

if (resource.loading) return <ApiState loading error={null} />;
if (resource.error) return <ApiState loading={false} error={resource.error} />;
const users = resource.data?.list ?? [];
```

新增接口时按以下顺序处理：

1. 在 `src/api/types.ts` 增加请求/响应 DTO。
2. 在 `src/api/adapters/types.ts` 增加 `ApiAdapter` 方法。
3. 在 `mock.ts` 实现本地数据和约 300ms 延迟。
4. 在 `http.ts` 增加 HTTP 路径、方法和请求体映射。
5. 在 `src/api/<module>.ts` 导出页面函数。
6. 页面只从 `src/api` 引入函数，并处理 loading/error。

## 7. 错误处理与联调验收

HTTP 模式下如果后端不存在、跨域失败或返回非 2xx：

- 请求层会抛出可读错误。
- 使用 `useApiResource` 的页面显示“数据加载失败”，而不是白屏。
- 保存类操作应在页面捕获异常后使用 toast 提示。

联调步骤：

```powershell
Copy-Item .env.example .env.local
# 编辑 .env.local，将 VITE_API_MODE 改为 http，并设置后端地址
npm.cmd run dev
npm.cmd run build
```

建议按以下顺序验证：登录 → 工作台 → 用户 → 角色/菜单 → 文章/分类/标签 → 日志/字典 → 分析页。

## 8. 后端实现注意事项

1. 时间字段建议使用 ISO 8601 或项目现有展示格式，并在同一接口内保持一致。
2. `id` 当前前端契约使用 `number`，后端应返回稳定数字 ID。
3. 删除接口可以返回 `204 No Content`，也可以返回 `{ code: 0, data: null }`。
4. CORS 至少允许开发地址 `http://localhost:5174`。
5. 分页查询建议支持 `page`、`pageSize`、`keyword`、`status`；文章额外支持 `category`。
6. 真正的鉴权必须由后端执行，前端权限控制不能替代服务端鉴权。
7. 如果后端错误码不是 `0` 成功，请统一修改 HTTP 适配器，不要在页面中分散判断。

## 9. 当前实现边界

- 核心业务页面已通过 API 层访问数据；部分纯演示页仍保留自包含的展示数据。
- `getVisitStats`、`getUserPortrait`、`getFunnel` 的 mock 返回结构已预留，HTTP 模式应返回完整数据。
- `getChatData` 的聊天结构以 `src/data/chatData.ts` 中的 `Conversation`、`ChatMessage` 为准。
- 生成额度接口沿用原有 `/api/v1/admin/generation-quotas` 路径，并已支持 mock/http 双模式。
